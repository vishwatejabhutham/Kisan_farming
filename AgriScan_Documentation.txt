

AgriScan
Crop Disease Intelligence Platform

Technical Product Documentation
Version 1.0  |  April 2026


Executive Summary
AgriScan is a four-layer crop disease intelligence platform that turns a simple WhatsApp photo from a farmer into real-time, GPS-tagged outbreak data. The same data that helps a smallholder farmer in Andhra Pradesh treat late blight today powers predictive inventory decisions for agrochemical companies tomorrow — and provides state governments with an early-warning system that has never existed before.

1.  Platform Overview

AgriScan is built on a single insight: every time a farmer photographs a sick leaf and gets an AI diagnosis, they are unknowingly contributing to the world's first real-time crop disease map. The platform converts that incidental data into a structured, monetisable intelligence product.

1.1  The core problem
India loses an estimated 15–25% of crop output annually to diseases. The information gap is structural:
	•	Farmers in remote areas have no access to agronomists.
	•	Agri-input companies (Bayer, PI Industries, Syngenta) pre-position inventory on gut feel, not data.
	•	State agriculture departments have zero real-time disease surveillance — they rely on paper reports that arrive weeks late.
	•	ICAR and the Agriculture Ministry cannot issue early warnings because they have no live feed.

1.2  The AgriScan solution
AgriScan closes this loop across four layers, each adding value to the next:

L1
Farmer App — WhatsApp-first, zero friction

L2
Disease Heatmap — live, GPS-tagged, block-level

L3
B2B SaaS Dashboard — predictive intelligence for agri-input companies

L4
Government Early-Warning API — crop disease surveillance for state departments

1.3  Why this data does not exist anywhere else
Every existing crop disease dataset is either: (a) self-reported by extension workers with multi-week lag, or (b) satellite-derived NDVI with no species-level disease identification. AgriScan generates ground-truth, timestamped, GPS-tagged disease data at the individual scan level. This is a genuinely new dataset.

2.  Layer 1 — Farmer App


Goal
Let any farmer diagnose crop disease by sending a photo on WhatsApp. No app install. Works on 2G. Replies in Telugu or Hindi within 5 seconds.

2.1  User journey
	•	Farmer sends a leaf photo to the AgriScan WhatsApp Business number.
	•	The Twilio webhook receives the image and calls the FastAPI backend.
	•	The backend downloads the image and sends it to Claude (claude-opus-4-5) with a system prompt instructing it to return structured JSON: disease name, severity, confidence, treatment, cost in rupees, and 3-sentence advice in Telugu and Hindi.
	•	The backend saves a Scan record to PostGIS (phone number SHA-256 hashed for privacy) and returns a formatted WhatsApp reply.
	•	The farmer receives: disease name in Telugu, severity level, exact pesticide dose, and estimated cost — all in a single message.

2.3  AI prompt design
The Claude system prompt instructs the model to return only valid JSON with the following schema:

{ "disease": string,
  "disease_telugu": string,
  "disease_hindi": string,
  "severity": "low" | "medium" | "high",
  "confidence": float (0–1),

2.4  Known limitations
	•	Image quality on 2G connections may be low — Claude handles degraded images but confidence drops below ~0.6 for very blurry photos.
	•	GPS coordinates depend on the WhatsApp client sending location — not all users enable this. Fallback: use the last known GPS if the phone hash matches a previous scan.
	•	Twilio sandbox is limited to pre-approved numbers during development.

3.  Layer 2 — Disease Heatmap


Goal
Aggregate every scan into a live, mandal-level disease map that shows outbreak clusters in real time — data that does not exist in any government or commercial dataset.

3.1  Data model
Every scan generates one row in the Scan table with the following fields:

Field
Description
id
UUID primary key
phone_hash
SHA-256 of the farmer's phone number
lat / lng
Float coordinates from WhatsApp GPS
location
PostGIS POINT (SRID 4326) — enables spatial indexing
crop
Crop type detected by AI
disease
Disease name (English)
severity
low / medium / high
confidence
Float 0–1 from AI model
district
Reverse-geocoded from Nominatim
mandal
Sub-district level from Nominatim
timestamp
UTC datetime of scan
raw_ai_json
Full JSON response stored for audit

3.2  Aggregation queries
The heatmap API groups scans at the mandal level and returns GeoJSON. Example output: '87 late-blight cases in Kurnool district this week, concentrated in 3 mandals.' Key PostGIS operations used:
	•	ST_AsGeoJSON — serialise cluster centroid for Mapbox
	•	ST_ClusterDBSCAN — spatial clustering for dense outbreak zones
	•	AVG(ST_X / ST_Y) — compute cluster centroid from individual points
	•	Noise filter: clusters with fewer than 3 cases are suppressed

3.3  Trend forecasting
The /api/forecast/{disease}/{district} endpoint computes a 7-day projection using linear regression on the last 30 days of daily counts. Confidence level (low / medium / high) is derived from the R² value of the regression. For production, Facebook Prophet or statsmodels ARIMA is recommended.

3.4  Caching strategy
Heatmap queries are cached in Redis for 5 minutes. This prevents repeated PostGIS aggregation on every dashboard refresh. Individual scan writes bypass the cache and go directly to Postgres.

3.5  Why PostGIS over alternatives
Database
Assessment
PostGIS
Native geospatial types, ST_* functions, spatial indexes — ideal for per-scan lat/lng storage and real-time clustering
Snowflake
No native PostGIS. Geospatial support is read-only H3/WKT — cannot do per-scan transactional writes. Good for batch analytics on top of PostGIS exports.
BigQuery
Strong geospatial analytics but no transactional writes per scan. Better as a downstream analytics layer.
MongoDB
2dsphere index supports point queries but lacks PostGIS clustering functions — would require custom aggregation pipelines.

5.  Layer 4 — Government Early-Warning API


Goal
Provide state agriculture departments, ICAR, and the Agriculture Ministry with an API that alerts them when any disease crosses a configurable case threshold in any district. Priced at ₹10L–₹50L/year.

5.1  The gap this fills
State agriculture departments currently have no real-time crop disease data. Their surveillance relies on extension workers filing paper reports — aggregated at best monthly, often quarterly. By the time a district office knows about a late-blight outbreak, it has already spread to neighbouring mandals.

AgriScan provides the first live crop disease feed for Indian government agriculture departments — equivalent to what IDSP does for human disease surveillance, but for crops.

6.  Database Architecture


6.1  Primary database: PostGIS
The core transactional store is PostgreSQL 15 with the PostGIS 3.3 extension. All individual scans are written here in real time. PostGIS spatial indexes make mandal-level clustering queries fast even at millions of rows.

6.2  PostGIS vs Snowflake — detailed comparison
This question arises because Snowflake is popular for analytics. The recommendation is: use PostGIS as the primary store, and optionally export aggregated data to Snowflake for BI tools if a B2B customer requires it.

Snowflake

Not designed for this. Bulk-load only. Per-row inserts are expensive.

No PostGIS. H3 grid and WKT geometry available, but no clustering functions.
Real-time queries
Sub-second on indexed columns with 10M+ rows
Seconds to minutes — columnar format is optimised for batch, not OLTP.
Local development

Cloud-only. No local instance possible.

6.3  Supabase recommendation
For the prototype and early production, Supabase is the recommended deployment target. It provides PostGIS, authentication, real-time subscriptions, and row-level security in a single managed service with a generous free tier. This eliminates the need to self-manage Postgres + PostGIS infrastructure.

6.4  Redis caching layer
Redis sits in front of the PostGIS aggregation queries. Heatmap and district summary queries are cached for 5 minutes with a simple key pattern: heatmap:{days}:{crop}:{disease}. Individual scan writes bypass the cache entirely.

7.  API Rate Limiting & Stability


Note
If you see: 'Request rate increased too quickly' from an upstream AI provider, this is a client-side burst issue — not a server error. The fixes below apply.

7.1  Root cause
Rate limit errors occur when the backend sends multiple AI API requests in a short burst — most commonly during the seed script (200 rows inserted simultaneously) or when testing batch WhatsApp webhooks. The AI provider detects an abnormal ramp in requests per second and returns a 429.

7.2  Fix 1 — Sequential delay
Add a delay between API calls in any loop:
import time
for item in items:
    result = call_api(item)
    time.sleep(0.5)  # 500ms between calls

7.3  Fix 2 — Async semaphore
For async/concurrent code, limit concurrent requests with a semaphore:
import asyncio
semaphore = asyncio.Semaphore(3)  # max 3 concurrent
async def safe_call(item):
    async with semaphore:
        return await call_api(item)

7.4  Fix 3 — Exponential backoff with jitter
Wrap every AI call in a retry with exponential backoff:
import time, random
def call_with_backoff(fn, max_retries=5):
    for attempt in range(max_retries):
        try:
            return fn()
        except RateLimitError:
            wait = (2 ** attempt) + random.uniform(0, 1)
            time.sleep(wait)
    raise Exception('Max retries exceeded')

7.5  Seed script guidance
The agriscan seed.py script inserts 200 fake scan rows. If it also triggers AI calls (e.g. to test the analysis pipeline), add time.sleep(0.2) between each call. For pure database seeding without AI calls, batch inserts are fine — the rate limit only applies to AI API requests.

11.  Glossary


Term
Definition
Mandal
Administrative sub-division of a district in Andhra Pradesh and Telangana, roughly equivalent to a block or tehsil in other states.
FPO
Farmer Producer Organisation — a collective of smallholder farmers. Key channel partner for initial farmer onboarding.
PostGIS
Spatial extension for PostgreSQL that adds geographic object types and functions such as ST_DWithin and ST_ClusterDBSCAN.
GeoJSON
Open standard for encoding geographic data structures; used by Mapbox to render heatmap layers.
SWR
stale-while-revalidate — a React data-fetching strategy that serves cached data immediately while re-fetching in the background.
APScheduler
Python library for scheduling recurring background jobs (e.g. hourly alert checks).
GeM
Government e-Marketplace — India's official procurement portal for government buyers. Primary route for selling Layer 4 contracts.
ICAR
Indian Council of Agricultural Research — the apex body for agricultural R&D in India.
DACFW
Department of Agriculture and Farmers Welfare — the central Agriculture Ministry.
DPDP Act
Digital Personal Data Protection Act 2023 — India's primary data privacy legislation.
